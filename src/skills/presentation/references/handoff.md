# Presentation handoff

Use this compact boundary when Presentation receives a governed source or brief.

## Source meaning

Record the source identity and current revision, audience and task, intended journey, semantic hierarchy, claims or requirements that must remain unchanged, meaning-bearing visual specifications, text alternatives, content-accessibility requirements, and known omissions or uncertainty.

## Realization brief

Record the medium and target surfaces, implementation constraints, interaction states, responsive or adaptive expectations, presentational accessibility expectations, imagery and asset limits, motion preferences, and inspection boundary. These are realization inputs, not new semantic claims.

## Return path

- Purely visual or interactive issue: refine the Presentation realization.
- Meaning-changing pressure: return a bounded question and evidence to the Document, Case, Frame, product authority, or supplied brief that owns the meaning.
- Source meaning changed: obtain a new source revision, invalidate affected realization and inspection evidence, and re-run the relevant checks.

Do not use a visual treatment, implementation convenience, or publication destination to settle a semantic disagreement.
