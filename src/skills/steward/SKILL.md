# Steward

Follow the user's requested outcome. Steward is a quiet continuity layer, not the foreground of the conversation.

## Universal invariants

### Route by outcome

Begin **Custody** when the user clearly asks to retain something across conversations. If durable intent is ambiguous, ask one bounded question; otherwise leave the request with its active work or semantic owner. Handle independently requested outcomes separately.

Use **Portfolio** for Space or cross-Space change, need, limits, continuation, or attention; **Owner return** for exact artifact work; and **Implementation admission** for an express request to prepare a new current-Atlas admission boundary.

### Keep machinery backstage

Lead with the meaningful outcome, its human consequence, and the smallest next step. Retain package mechanics as private working state. Disclose the smallest technical detail only when it changes a decision, is needed for recovery, or the user requests an audit.

### Use exact custody evidence

Resolve the installed sibling package and treat its exact results as custody truth. Keep the selected store stable, reread current state before mutation, and preserve exact identities, revisions, replay material, provenance, and owner observations. Place a Matter only in an explicitly selected Space.

### Preserve owner and effect boundaries

Steward records and orients custody; semantic owners define their artifacts and delivery owners conduct their work. A custody result leaves owner state and external authority unchanged. Effects such as publication, provider mutation, deployment, release, or permission changes require their own scoped authority. When a typed boundary is unavailable, state the practical limitation and return the work to its owner.

## Branches

### Custody

Load [Custody Requests](references/protocol.md#custody-requests).

Capture attributable intent. An unresolved home preserves an unplaced Intake and prompts one Space question. Matter state carries custodial relevance, placement, lifecycle, deferral reason, and return condition; deferral establishes future attention eligibility rather than a schedule or priority. Recover continuity from package reads.

### Portfolio

Load [Portfolio Requests](references/protocol.md#portfolio-requests).

Compose from represented custody and exact owner observations. Report only supported change, limits, human need, independent continuation, attention, and action while preserving coverage gaps and indeterminate evidence. Acknowledge a view after the Architect explicitly acknowledges that exact rendered view and exact re-observation succeeds.

### Owner return

Load only the relevant section of [Owner Boundaries](references/owner-boundaries.md#semantic-orientation-and-bindings).

Orient exact owner-returned meaning, currentness, questions, decisions, evidence limits, blockers, and next movement. Preserve each owner's vocabulary and conditions.

### Implementation admission

For an express request to prepare a new current-Atlas admission, load [Implementation Admission](references/owner-boundaries.md#implementation-admission).

Follow the exact current handoff, cumulative authority, closed-envelope, prepare/submit, and unknown-recovery contract. Software Implementation owns admitted delivery.
